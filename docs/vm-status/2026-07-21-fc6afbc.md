## Why this doc

The prior handoff's readback proved two things at once: (1) the retargeted vehicle
(`progression_recurrence_free_survival_1_yr`) banks cleanly and the v1_5→v1_6 bump is a genuine
**content no-op** — a person_id-keyed inline re-comparison found CT/EHR/text byte-identical for all
5 shared patients, both experiments; (2) the prescribed `diff_golden --mode strict` gate itself
still returned `GATE FAILURE`, because `diff_golden` hard-joined BEFORE/AFTER on the `index` field
— a positional BQ row enumeration (`df['index'] = df.index` in `run_bq.py`), not a stable identity
key. The source table's 32→38 column growth shifted row order, so `--limit 5` captured the same 5
patients under different `index` values → 0 shared indices, an empty (and therefore vacuous)
intersection. The bump was never the problem; the verification vehicle's join key was.

**Fix (this re-plan):** `diff_golden.py` now joins on `person_id` instead of `index` — every golden
record already carries it, and task tables are one-row-per-person, so it's the actual identity key
(stable regardless of row-count/order changes upstream). Fixed at the tool's **default**, not a new
`--join-key` flag every caller would have to remember to pass — the Step 0b command below is
**identical** to the one in the superseded doc; only the code being executed differs. See
`docs/plans/vlm-step6-pathology-live-substrate.md` (Phase 0 Step 0b, "Re-plan 2026-07-21, second
correction") and `src/vista_run/diff_golden.py` for the full rationale. Step 0a's schema-diff
already ran and passed on the VM (2026-07-21) — that verdict stands and is **not** re-run here.
