## Why this doc

`EHRAdapter`/`ehr_filters.py` were fully built but unused — the real hot path
(`run_bq.py:_build_prompts_for_experiment`) still substituted the pre-rendered `patient_string` CSV
column. This branch wires the real path: `presets.py`'s `_ehr_block` now emits concrete
`window`/`code_filter` chains, and `run_bq.py` adds `_apply_ehr_adapter` (called at the top of
`_build_prompts_for_experiment`) that parses each patient's real LUMIA `.xml`, runs the filter
chain, and renders via the canonical flat-renderer — **fail-closed**: a patient with no resolvable
LUMIA file is dropped from the experiment entirely (Phil's call, no fallback). None of this has
touched real data yet. This doc proves it's correct (byte-diff where provable, human eyeball where
it isn't) and produces the rendered HTML batch Phil asked to personally review before this becomes
default behavior.

**PHI discipline throughout:** report counts, field names, exit codes, and file paths back into
this doc's readback section — **never** raw timeline text, person_ids, or the byte-diff tool's
printed BEFORE/AFTER previews (`diff_golden.py` prints those on failure; summarize instead).

## Step 2 — Phase 1: decision gate — does the `timeline` variant need `code_filter`?

**Precondition fix (already encoded into this render):** `iter_captured_examples` runs
`_build_prompts_for_experiment` (where fail-closed filtering happens) *before* its stable-sort +
`head(limit)` step (`src/vista_run/context_capture.py:190,195,198`). So an unrestricted `--limit 20`
would draw the **after** bank from only *covered* patients but the **before** (pre-wiring) bank from
the first 20 in sort order regardless of coverage — the two banks' index sets could diverge for a
reason that has nothing to do with `code_filter`, and `diff_golden` hard-fails on index-set mismatch
(`src/vista_run/diff_golden.py:121-133`).

**Fix:** before banking, restrict the input to *only* Step 1's confirmed-covered `person_id`s. No
existing loader flag does this (checked: no `allowlist`/`person_id_filter`/`restrict_ids` parameter
anywhere in `run_bq.py` or `data_tools/utils/*.py`) — build a one-off restricted mirror: copy
`<VM_CONFIG>`'s `paths.base_dir` tree into a scratch dir (symlink everything except the timeline CSV
for `progression_recurrence_free_survival_1_yr`), row-filter that one CSV down to the covered
`person_id`s (`pandas.read_csv` → `df[df.person_id.astype(str).isin(covered_ids)]` → write back),
and point a scratch config's `paths.base_dir` at the mirror. Every row is then covered by
construction, so the fail-closed drop is a no-op for both banks and `head(20)` draws from the
identical set.

```bash
# --- "before" bank (pre-wiring parent 6ded1e6, in a throwaway worktree) ---
git worktree add ../vista_eval_vlm-prewiring 6ded1e6
cd ../vista_eval_vlm-prewiring && cd src
python -m vista_run.golden_harness \
  --config <ABS_PATH_TO_RESTRICTED_SCRATCH_CONFIG> \
  --type gemma3 --name google/medgemma-1.5-4b-it \
  --task progression_recurrence_free_survival_1_yr \
  --experiments no_image \
  --tag legacy_small --limit 20
cd ../../vista_eval_vlm

# --- "after" bank (this branch, select=[] as currently committed in presets.py) ---
cd src
python -m vista_run.golden_harness \
  --config <RESTRICTED_SCRATCH_CONFIG> \
  --type gemma3 --name google/medgemma-1.5-4b-it \
  --task progression_recurrence_free_survival_1_yr \
  --experiments no_image \
  --tag lumia_live_nofilter --limit 20

# --- diff ---
python -m vista_run.diff_golden \
  <results_dir>/golden/.../progression_recurrence_free_survival_1_yr_no_image_legacy_small_golden.jsonl \
  <results_dir>/golden/.../progression_recurrence_free_survival_1_yr_no_image_lumia_live_nofilter_golden.jsonl \
  --mode strict
cd ..
```

**Expected/Stop (resolve inline — this is a pre-anticipated class-2 decision gate, not a novel
deviation):**
- Index-set mismatch even against the restricted input → **STOP** (a distinct, unexpected
  precondition failure — hand back, don't interpret as a `code_filter` verdict).
- **Strict PASS** → `timeline` needs **no** `code_filter` — `presets.py`'s `_ehr_block` already has
  `select = []` for the `timeline` variant (current committed state) — done, no code change needed.
- **Strict FAIL** (index sets matching) → re-bank the **after** side with `code_filter
  (exclude_stanford=True)` added (`--tag lumia_live_filtered`), re-diff strict. Whichever
  configuration passes byte-identical is the answer — **edit `src/context/presets.py`'s
  `_ehr_block`**: change the `elif variant == "timeline":` branch's `select = []` to
  `select = [{"fn": "code_filter", "exclude_stanford": True}]`, update its docstring to say the gate
  resolved this way (remove the "pending Phase 1" language), commit on this branch

- **Both** pass strict → byte-identical on this sample (`code_filter` is a no-op here) — keep
  `select = []` (simpler, maximally permissive) and note this outcome explicitly in the readback
  rather than picking silently.
- **Neither** passes strict → **STOP** (class-3 — a third variable is at play; hand back, don't
  guess).
**Clean up the worktree after:** `git worktree remove ../vista_eval_vlm-prewiring`.
**Destructive:** no — local golden-bank writes under the git-ignored results tree only.

Inspect residual `TEXT_FIELDS` diffs and classify — keep this **objective**, not open-ended VM-time
invention. Any regex added to `diff_golden.normalize_text` (`src/vista_run/diff_golden.py`) must be
field-local and event-line-local, preserve line count/event order exactly, preserve CODE/description/
note-text byte-for-byte, only normalize numeric VALUE-line equivalence within a bounded tolerance,
and never be a catch-all substitution:
- **PASS / declared-delta, safe to encode:** (a) VALUE-line numeric formatting differs but parses to
  the same float (LUMIA has no discrete `numeric_value` attr — parsed from element text/`text_value`,
  a known delta per OQ-K); (b) UNIT token differs only in spelling for the same concept (LUMIA's
  `unit_source_value`, ~42% field coverage per the 2026-07-06/07 check, vs legacy's original key).
- **STOP (genuine bug):** any event-order or event-count drift, any `STRUCTURE_FIELDS` drift (always
  hard, mode-independent), any CODE/description/note-text content difference, or a residual class
  outside (a)/(b) — e.g. truncated note text, a dropped patient.
- **STOP (explicit, not a soft flag):** if the declared-delta fraction gets pervasive enough that a
  human spot-check stops being credible, hand back to Phil for review — report the % and field
  breakdown, don't auto-proceed.
- **`--lenient` is for local iteration only, never the committed gate.** The final committed run
  must use `diff_golden` **without** `--lenient` and print `RESULT: ALL GATES PASS`.
