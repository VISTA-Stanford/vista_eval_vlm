Four small code seams + a fresh 0b re-run.

Seams (steps)

Seam 1 — Decoding fix: constrain off the mapping, not is_binary run_bq.py

Gate the constraint on the task's mapping being binary Yes/No via is_binary_yes_no_task(mapping) (final_metrics.py:70). PFS's 3-class mapping passes (predicate reads only the "1"/"0" keys — Codex-confirmed). Faithful to Ryan's baseline commit 5e97abd, which forced Yes/No for every Yes/No-mappable task before the is_binary knob existed.

Files: src/vista_run/run_bq.py (~:905-910). task_info is a raw registry entry (loaded :67-71), so task_info.get("mapping") is available at the gate — provided the entry carries mapping (VM-side fact, made fail-closed by seam 3).
Seam 2 — Instrumentation: per-task [DECODE] log + summary run_bq.py

Immediately after the gate, emit the decode mode per task plus a per-run summary count of constrained tasks (makes constraint breadth observable, per OQ-F2). mode=free prints the reason. Inference-neutral.

[DECODE] task=progression_recurrence_free_survival_1_yr  mode=constrained  choices=['Yes','No']  (mapping is Yes/No; use_constrained=True)
[DECODE] summary: 1/1 selected tasks constrained
Seam 3 — Fail-closed preflight: assert the mapping BEFORE weights load run_rung0_gpu.sh

The real fix for the silent no-op. Extend the existing preflight to resolve the registry via the same cfg['paths']['valid_tasks'] run_bq uses, and for each task in the config's tasks: list assert is_binary_yes_no_task(mapping). Any selected task whose mapping is not Yes/No while the flag is on → FAIL before GPU spend (the guard that must go RED). Runs on the GPU box (base_dir is a VM mount), costs no weights.

Files: eval/run_rung0_gpu.sh (preflight block).
Seam 4 — Eval fix: constrained reducer, registry-by-contract, rung-0 output constrained_all_model_response.py

Use constrained_all_model_response.py (direct Yes/No map, no extraction, :188) which drops ground_truth_label == -1 rows (:259-261) — the ~27% insufficient class. Three fixes make it safe:

Gotchas

The flag was AND-gated behind is_binary — necessary but not sufficient

run_bq.py:910: ["Yes","No"] if (task_info.get("is_binary", False) and use_constrained) else None. PFS is is_binary: False (genuine 3-class), so the flag was a silent no-op. This is the OQ-R6 miss this plan corrects.

The reducer's default output path IS Ryan's committed baseline comparator

Running 0c with the default --output would overwrite figures/results_stats/all_model_response.csv (the very file we compare against) and dirty git. Always pass a rung-0-specific --output.

The reducer's "Dropped N rows" print reports group-count, not rows

:261 prints len(minus_one_count_gt) = number of model groups. The 27%-drop QC would read a garbage number unless the print is fixed.

No python on the planner Mac — Phase 1 is structural review only

Codex caught that a Phase-1 python -c ast.parse check violates the no-execution posture. Phase 1 is rg-based structural review; any AST/import check runs on the VM.
