TL;DR

Pathology inference has been reading a frozen, hand-generated CSV two dataset versions behind the rest of the repo, produced by a one-shot script hardcoded to one engineer's local VM cache — while `vista_bench`'s real pathology substrate (slide-linking, stain classification, LLM-extracted labels) only landed in vista_bench_v1_6. This plan bumps the shared VISTA_BENCH_DATASET constant to v1_6 (Phil's explicit call — whole-repo, not a pathology-only knob), re-verifies CT/EHR/text aren't broken by that bump as a gated prerequisite, then adds the first-ever live BQ query for pathology and re-tiles whatever slide delta surfaces. No legacy baseline exists to byte-diff pathology against, so the landing gate is a human-QA render via the existing config-context viewer — the same mechanism Step 5 converged on.
