TL;DR. A weight-free CLI (context_viewer.py) that renders exactly the context a given (config, task, experiment, model) feeds each VLM — the assembled prompt plus the selected CT slices / pathology tiles (post-window, model-ready) as base64 thumbnails, with a token-budget bar — into one self-contained HTML file. The concrete use is Phil's manual pre-run input QA: before a full eval run, eyeball a small subset of examples across a couple of tasks to confirm the inputs look right (prompt well-formed, right slice counts, no unexpected 0-image rows). It shows inputs, not answers — it instruments the pipeline, it doesn't score it. The hard requirement is zero drift with inference: it reuses the same weight-free capture loop the golden harness runs, so it shows what the model actually receives — not a re-derivation. Scope = the viewer + two enabling seams only (a shared capture core + a per-adapter context_window); Phase 1 framework, golden harness, model-load split, and supports_inline already landed on main.

Knobs & contracts

CLI — --type/--name (Ryan's convention)

context_viewer \
  --config <cfg> --type <gemma3|intern> --name <model> \
  --task progression_recurrence_free_survival_1_yr \
  --experiment <name> [--limit N] [--batches] [--out]
--type/--name = MODEL_REGISTRY key + model HF name — Ryan's convention across the whole repo (run_bq.py, legacy run.py, golden_harness.py, every eval script; roster is a model_type|model_name list; no --model flag exists). --experiment is singular, resolved through normalize_experiments. No --results-csv — the viewer shows inputs, not scoring (Q3).

Two enabling seams

1. Shared weight-free capture core — context_capture.py holds iter_captured_examples() + CapturedExample (carries the preprocessed PILs). Both golden_harness (hashes) and the viewer (thumbnails) consume it → zero drift.

2. Token budget — tokenizer-only load (no GPU) for exact text tokens, divided by a new per-adapter context_window. A tokenizer miss is a preflight STOP (Q1), so the bar is always a real count. Image tokens are model-specific & not weight-free computable → shown as a separate chip.

Byte-identity constraint: same record field names + order and the same json.dumps(...) kwargs (sort_keys/ensure_ascii/separators) the current writer uses — the extraction moves the loop, not the record shape or serialization.

Add context_window: int | None = None to BaseVLMAdapter; set per adapter from each load()'s max_model_len (see the Knobs table). None → the bar renders "context window unknown" (no false denominator).

NEW D. Build context_viewer.py + the token counter

CLI & resolution: mirror golden's --type/--name (Ryan's repo-wide convention; no --model); resolve --experiment through context.normalize.normalize_experiments(orch.cfg) (bare string resolves directly; a block-list dict resolves via its name).

Preflight (fail-closed, before any render): reject (i) retrieval, (ii) model-backed summarize, (iii) unknown / ambiguous --experiment, (iv) invalid --type; (v) the standalone tokenizer-only load must succeed — miss → hard STOP (Q1). Assert no weights path is hit.

Verification & VM handoff

SIMPLE handoff phil-sllm-01 · weight-free · run + readback co-located

One repo, one executor class (Claude-Code CPU box), no cross-repo SHA ripple, no bank/un-bank beyond the one pre-refactor golden baseline, no destructive writes, no non-Claude runner script. A tokenizer miss is a preflight STOP (halt-and-report), not a class-2 decision gate — so this stays SIMPLE. Every smoke runs on a small subset (small --limit N) — pre-run input QA, not a full pass.

What runs on the VM

  1. golden byte-identity regression — re-bank a small golden post-refactor, diff_golden --mode strict vs a pre-refactor bank of the same (task, experiment, model, N).
  2. run the viewer on the canonical smoke — small subset — context_viewer … --task progression_recurrence_free_survival_1_yr --experiment <ct-bearing> --type <gemma3|intern> --limit N with N small (≈5); then a no_image experiment; open each HTML.
  3. preflight / edge cases — retrieval / summarize / unknown-experiment / invalid-type all fail-closed; dict experiment resolves or rejects cleanly; a model whose tokenizer won't load → STOP with a diagnostic (Q1).

Expected-vs-unexpected envelope

Accepted (resolve inline): context_window == None adapter → bar reads "unknown" (only a wrong denominator is unexpected).
Stop (halt): golden gate failure / index-set mismatch; tokenizer load fails → preflight STOP (report model + likely cause); HTML references any external URL or leaks a local image path in src; a CT-bearing row renders 0 images or a wrong slice count (drift); weights/GPU touched (preflight didn't fail-closed); any reject case that doesn't fail-closed.

PHI: the HTML embeds real timelines + imagery → su-vista mount only, git-ignored, never committed; readback reports counts / file existence / slice counts / token numbers only. /phi-vet gates the code commit.

Gotchas

Render off PromptDataset, NOT the assembler
The flat question/image that reaches the model is produced by PromptDataset.__getitem__ (CTAdapter.contextualize + inline pathology-tile load) + _build_prompts_for_experiment — not Assembler.to_flat_item. The assembler is only partially wired into the hot path; rendering via it would show context inference doesn't actually feed. Use context/ block metadata for provenance labels only. Codex-confirmed
Weight-free, but VM-only (reads real PHI)
TaskOrchestrator.__init__ builds bq_client + storage_client and the path reads real PHI (run_bq.py:99,102). No GPU / no weights, but this runs on the VM like the golden harness — not on the Mac.
Why a tokenizer cache-miss happens (Q1) — and why it STOPs
A miss is diagnosable, not random. TaskOrchestrator._set_envs redirects HF_HOME to cfg['runtime']['cache_dir'], so a tokenizer in the default ~/.cache/huggingface looks missing — and the same redirect hides the hf auth login token → gated-repo 401 for gemma/medgemma. A weight-free viewer can also run for a model whose weights/tokenizer were never downloaded; the PHI VM may be offline. So the load is a preflight precondition: miss → STOP naming the model + likely cause; Phil picks the remedy when it fires (stage the tokenizer / forward the token / relax to an estimate).
summarize fails closed at preflight
The summarize cluster is a deferred, model-backed step (not weight-free). A viewer that silently skipped it would misrepresent the context, so it's rejected at preflight — consistent with assembler.preflight fail-closing inline_by_timestamp.
