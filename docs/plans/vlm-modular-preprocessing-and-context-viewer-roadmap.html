What this is. Dissolve the experiment god-enum into per-modality adapters that emit uniform ContextBlocks (id, modality, payload, metadata), selected at the leaf (CT slice, pathology patch, EHR a filter chain) and composed by an assembler (ordered now; inline_by_timestamp in Phase 1.5). EHR consumes the full LUMIA timeline as input and runs its filter chain + flat-render + truncate live at inference — full parity with CT slice / patch / truncation / assembly; no offline prep, no meds_tools. A weight-free config-context viewer renders exactly what the model receives.

Knobs & contracts

EHR consumes LUMIA as input — live at inference (serialization interrogation 2026-07-06)

The full per-patient LUMIA timeline (gs://vista_bench/thoracic_cohort_lumia/{person_id}.xml) is given as input — the expensive OMOP → LUMIA serialization is done upstream. The EHR adapter ingests + parses LUMIA, runs the filter chain, flat-renders to today's line format, and truncates — all live at inference. No offline prep, no re-materialized patient_string CSVs, no meds_reader/ontology/meds_tools in-repo. Changing an EHR select/serialize value is a live edit, at parity with CT slice / patch / truncation / assembly.

meds_tools — NO LONGER A DEPENDENCY (OQ-G superseded 2026-07-06)

  • Consuming LUMIA deletes the get_described_events_window fetch — the only DB+ontology consumer — so the SHA-pin e2a2a59, the spurious requires-python >=3.14 floor, and the hardcoded local-path [tool.uv.sources] are all moot.
  • Flat-render spec: the local meds_timeline_utils.get_llm_event_string (imports only re + pandas) is vendored into the EHR adapter as the field-for-field format spec — same discipline as lifting truncate_timeline verbatim.
  • STANFORD/report skip = a code_filter row-drop (the old exclude_report kwarg disappears). A third formatter copy exists (test_meds_tools.py:6) — consolidate.
  • ⚠ VM precondition (byte-identical hinges on this): confirm the LUMIA corpus carries the flat renderer's fields (numeric_value / unit / note text_value / a distinct description) and covers the eval cohorts — markup.md is abbreviated. A missing field → gate-3 declared-delta (OQ-K); partial coverage → DB-fetch fallback for the gap only.

Leaf selectors + reuse notes

  • CT slice: evenly_spaced_k, every_n, center, center_k, slice_range, all.
  • Pathology patch: random_n(n, seed), all; future tissue_top_n.
  • Truncate: lift truncate_timeline verbatim — the first_4_rows=''-never-populated quirk is byte-preserving for golden gate 1; don't "fix" it during the lift.
  • Summarize: a small cluster lift (_summarize_timeline_for_context + _run_vlm_* + TIMELINE_SUMMARY_TEMPLATE) with a raw-timeline-on-exception fallback to decide. Model-backed → not weight-free; the viewer rejects/marks it.
  • Not built here: study/series & specimen/block/slide — upstream in VISTABench (verified: vista_bench dedups one image per person). Re-add is a cross-repo change.

Inline capability contract (seam in Phase 1; wired in Phase 1.5)

Adapters front-load all images before text (gemma3.py:43-77, qwen3.py:46-73); 8+ registry models, only gemma3/qwen3 would get a rewrite → fail-closed is the common case. Spec: add supports_inline: bool = False to BaseVLMAdapter; the assembler receives the resolved adapter (not a bare model_type, avoiding a context→models import cycle) and raises at preflight (before weights load) when a config requests inline on an unsupported model (OQ-D).

  • Gate 2 — by_model. Image bytes identical per model.
  • Gate 3 — EHR LUMIA-render delta. LUMIA-ingest + live filter + flat-render vs the current patient_string, within a declared allowlist where "ordering" = within-line field order ONLY; event/line order identical. ⚠ Runs on the live inference path — no CSV to regenerate. Assert the LUMIA-derived dynamic_prompt matches today's, and a filtered config drops exactly the right events. Conditioned on the LUMIA field-coverage check (missing field → declared-delta, OQ-K).
OQ-K Byte-equality is the target — gate 1 for imaging/structure, gate 3 for the EHR string (verified on one example); declared-delta fallback OK (for the EHR string, the LUMIA-field-coverage escape hatch); cross-version repro not a goal.
