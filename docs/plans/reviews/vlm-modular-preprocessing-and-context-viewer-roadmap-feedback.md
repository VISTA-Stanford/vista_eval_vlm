## Failure Modes
- Scenario | New dict experiments run inference but results scripts silently drop them | The plan focuses on `run_bq.py` back-compat, but `final_metrics.py` and `all_model_response.py` use config `experiments` as hashable filter values | What to add: a shared `normalize_experiments(cfg)` helper returning `(name, spec)` and update all result discovery code to use names.
- Scenario | Viewer says it reuses inference path but accidentally requires model weights | Current `TaskOrchestrator.__init__` always loads the model and processor | What to add: split data/prompt/dataset setup from model loading, or define a lightweight viewer loader that reuses shared functions without constructing `TaskOrchestrator` as-is; cite that current model load is at src/vista_run/run_bq.py:102.
- Scenario | Golden-output tests pass structurally but miss user-visible prompt changes | Byte-identical `dynamic_prompt` and slice indices are sound behavioral checks, but only if generated from the same rows, same truncation config, same prompt maps, and stable CSV ordering | What to add: fixture selection rules, row identity checks by `index`/`person_id`, and explicit assertions on full `dynamic_prompt` strings rather than substring-on-rendered-output asserts.
- Scenario | Path selector duplicates tile extraction logic or changes folder matching | The plan correctly says sampling should lift from `run_bq.py`, but path tooling already owns extraction and folder layout | What to add: path selectors should accept already-materialized tile paths and must not call or duplicate WSI tiling; keep folder-name resolution behavior covered by tests.
- Scenario | `used_image` is too coarse for selector verification | Current CSV output records only 0/1 image use, not image count or CT indices | What to add: for verification/viewer only, expose selected indices/counts before inference, or make the viewer/golden test inspect dataset items directly on the VM.

## Modularity vs. YAGNI
- CT selectors | Plan's current choice: `src/preprocess/ct_selectors.py` registry | Modular alternative + realistic use case: a small pure function registry supports the explicitly requested `every_n`, existing evenly-spaced counts, and future `range`/`all` without touching `vqa_dataset.py` | Recommendation.
- Path selectors | Plan's current choice: local `path_selectors.py` with `random_n` and `all_tiles` | Modular alternative + realistic use case: selector over existing tile path lists, with budget/seed knobs for 100 vs 125 and deterministic viewer/debugging | Recommendation, but require reuse of `tile_wsi.py` extraction output rather than new WSI extraction logic.
- Text composers | Plan's current choice: new `text_composers.py` converging onto meds_tools | Modular alternative + realistic use case: named prompt compositions for timeline/report/path_note/retrieval remove real branching | Recommendation only if composers call a single meds_tools-backed adapter; do not introduce a third formatter copy.
- Cohort axis A | Plan's current choice: defer to Phase 4 | Modular alternative + realistic use case: a cohort-source registry would reduce six loader branches, but output/resume contracts and CSV schemas make it higher blast radius | Recommendation: keep deferred and raise to user after B-E lands.
- Viewer | Plan's current choice: static HTML | Modular alternative + realistic use case: debugging selected CT slices/path tiles and PHI-bearing prompt context before GPU spend is concrete and aligned with “instrumentation” | Recommendation, but define a no-model-weight loader path.
