The two axes (the crux)

Refactor axis (3b): legacy __getitem__ CT branch → CT adapter. Byte-identical, both golden sides on feb26. This is what the golden gates.

Substrate axis (v1_1→v1_5/feb26): expected to change cohort + image bytes. NOT byte-gated — validated by row-count sanity + the re-banked EHR baseline.

Holding the substrate fixed on feb26 across the 3b refactor is what makes the byte-identity diff meaningful again.

Verification & VM handoff

Weights-free golden harness on the GCP VM. Canonical smoke = PFS × gemma3 medgemma-1.5-4b-it (+ intern InternVL3_5-8B-hf for Gate 2 grayscale).

Step 1 — v1_5 CT resolution smoke Phase 1

Expected: feb26 blob downloads; image_count > 0; 30 evenly-spaced selected_indices; grep the [CT] source= prefix= blob= file= trace → source=gcs, blob from the UID path, nifti_path never read.

Stop: feb26 404; any [CT] fall-through to nov25; image_count == 0 across all rows.

Accept/reject schema guard: row with UID → resolves; row missing UID → fail-closed no-image (resolve_ct_blob → None), never reaches for nifti_path. Exercise one of each.

Step 1b — coverage report (soft; human gate) Phase 1 Phil gate

Report — aggregate metrics only in the committed doc (detailed per-row → GCP-mounted su-vista bucket, OQ-Q4): cohort size; count resolving to a feb26 blob; null/missing UIDs; count whose resolved series differs from v1.1 (if derivable).

Control flow: Steps 1/1b/2 batch in the same VM doc; divergence is never a failure; but Step 3 must not bank C1 until Phil records accept/revise.

Routing: accept → Step 3 · not acceptable → STOP + re-plan · null UIDs beyond agreed shape → class-2 deviation.

Floor (OQ-Q3, resolved): the executor reports the coverage and Phil decides in flight on the VM; ~87% (≈ rung-0's 86.9%) = healthy reference prior, materially below (~80% or less) = suspect the v1_5 link/query. Link-health check, not an eval bar.

Step 2 — re-bank EHR no_image baseline on v1_5 Phase 1

Expected: non-null prompts; image_count == 0; assembly_mode == "ordered"; .meta.json row_count == jsonl lines, sorted; repo git-clean. Report shape units: total rows, unique person_id, CT-bearing UID rows, timeline-non-null rows, PFS count.

Stop: row_count == 0; meta ≠ jsonl lines; missing/zero-byte output; dirty repo w/ golden; timeline/embed_time shape-shifted.

Step 3 — bank axial "before" on feb26 (C1) Phase 2

Two invocations (--tag legacy_feb26): gemma3 google/medgemma-1.5-4b-it and intern OpenGVLab/InternVL3_5-8B-hf.

Expected: per (experiment, model) non-empty sorted .jsonl + .meta.json; image_count > 0 for CT-bearing rows; matching-length image_hashes; weight-free.

Stop: traceback; row_count == 0; missing/zero-byte output; index set not unique-and-sorted; unexpected retrieval-skip / "no data" for axial_all_image; weights loading.

Step 4 — 3b refactor diff (C3 + C4) Phase 3

diff_golden.py <legacy> <adapter> --mode strict per model (strict is default — state it).

Expected: shared-index set identical; Gate 1 byte-identical over image_hashes / selected_indices / image_count / assembly_mode / path_tile_count (None for CT); Gate 2 per-model hashes identical; RESULT: ALL GATES PASS.

Stop: any Gate-1/2 drift; index-set mismatch; [WARN] no shared indices (empty intersection cannot prove a no-op).

Step 5 — gate-3 EHR diff (D3) Phase 3

diff_golden.py … --mode allowlist.

Expected: event/line order identical; deltas confined to the declared numeric_value allowlist.

Stop: gate-3 outside allowlist beyond numeric_value → hand back for D3.

PHI-clean readback: counts by field, affected indices, ≤5 field-name/index examples + scrubbed characterization only. Do NOT paste diff_golden BEFORE/AFTER previews — _preview prints raw prompt/timeline values (diff_golden.py:169-170,185-186) = PHI.

Handoff phasing (3 phases + Mac interlude)

Why phased: class-2 human gate at 1b + bank-before/diff-after goldens + a Mac implementation interlude (Step 3 banks "before" → 3b implemented on the Mac, SHA moves → Step 4 banks "after"). So C1 and C3/C4 are at different SHAs by construction.

  • Phase 1 — Steps 1/1b/2 (VM). Gate: Phil accepts coverage before C1.
  • Phase 2 — Step 3 C1 bank. Then hand back to Mac for 3b.
  • Phase 3 — Steps 4/5 after 3b. Gate: D3.

Banked-by-SHA rule: if any code/config/data input moves after a banked phase, un-bank and rerun the affected golden. Render as two vm-status docs or one superseding chain (see OQ-Q5). Executor class throughout = Claude-Code CPU / weights-free (no GPU, no runner script, no run-vs-readback split).
