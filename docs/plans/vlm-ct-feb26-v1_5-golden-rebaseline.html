TL;DR

Rung 0 first: the rest of this plan only exercises the weights-free golden harness — it never loads model weights or emits a results CSV. So before migrating, reproduce Ryan's real weighted pipeline on feb26 on a near-untouched v1_1 substrate (change only the CT storage prefix to feb26 via a config seam, force GCS) to prove we can drive the VM and reproduce his workflow — a report milestone, not a byte gate. Then rung 1 cuts the substrate v1_1 → v1_5 (the nov25 CT snapshot is deleted; feb26/v1_5 links CTs via image_study_uid+image_series_uid, not the dropped string nifti_path). Then rung 2 dissolves the CT branch into an adapter, gated byte-identically on feb26. The crux stays: keep the refactor axis (3b, byte-gated, both sides feb26) separate from the substrate axis (v1_1→v1_5, an expected results change, not byte-gated).

Gotchas

Committed config can't run the rung-0 smoke as-is

all_tasks.yaml lists 5 models (eval/bq_gcp.sh MAX_MODELS=4 rejects >4), its only active task is has_recurrence_1_yr (PFS commented at :40), and every experiment is commented out (:67-74 → run_bq defaults to no_image only, never axial_all_image). Rung 0 needs a VM-local uncommitted overlay: 1 model, PFS, [no_image, axial_all_image], subsample:true, v1_1, ct_snapshot_prefix: feb26, force GCS.

Force GCS or the smoke silently uses local nov25 bytes

ct_dir points at a local nov25 download tried before GCS. If it survives, the run loads local nov25 and never proves the feb26 reroute — so the rung-0 gate run unsets ct_dir (force GCS). The local-cache exact run is a separate ryan_exact_local outcome, not the gate. And after the prefix flips to feb26, a stored nifti_path embedding .../nov25/... no longer hits the startswith(prefix) early return; the else-branch reconstructs feb26 for .nii.gz-terminated paths — verified per-shape by the 0a preflight (OQ-R4).

nov25 is fully deleted — not a fallback

The roadmap's "feb26 primary, nov25 fallback" line is dead: gs://su-vista-uscentral1/…/vista/nov25 has zero objects. Drop the fallback entirely.

v1_5 drops the string nifti_path (now deprecated INTEGER)

CT links are image_study_uid+image_series_uid; the whole _nifti_path_to_blob_and_filename heuristic is obsolete in rung 1. Reading nifti_path in v1_5 gets an INTEGER. (Rung 0 stays on v1_1, where nifti_path is still the string selection.)

feb26 link keys only exist in v1_5 → substrate cut is forced, not optional

In rung 1 you cannot resolve any feb26 CT without v1_5's study/series UIDs, so D1 (rebuild golden on feb26) implies D2 (cut to v1_5). The old nov25 baseline is unusable as a 3b "before" — but not because a pixel diff is proven: nov25 is deleted, so whether the reprocess changed voxels is unverifiable, and series-selection has changed since v1.1 anyway. Both golden sides run on feb26, so it doesn't matter.

Repo has no text→number parser (D3 grounding)

Every VALUE line (get_llm_event_string:225, format_events.py:103, test_meds_tools.py:43) builds from a discrete field sourced from the DB — never parsed from text. The LUMIA .xml is generated upstream (no generator here). So "parse numeric from element text" = a new speculative parser → deferred; the real fallback is upstream (OQ-N).

Don't commit all_tasks.vm.yaml as the default config

The executor's localized .vm copy points at su-vista-* mounts; the committed all_tasks.yaml stays on the GCS gs://vista_bench/ layout. The rung-0 overlay is likewise VM-local and uncommitted.

Historical CT test set — cohort recoverable, individual files not

nov25 was deleted because the CTs were reprocessed into feb26 under the same (study, series) UIDs — so the same scans likely still exist at the feb26 path. But there is no file-level record of what earlier runs tested: ct_test.py logs only counts, and the golden harness captures person_id/index/pixel-hash (golden_harness.py:149-155), never a filename/UID. What is recoverable is the cohort: committed figures/data_stats/person_id_subsampled.csv pins the person set, and person_id → (study, series) is a stable v1_5 BQ join — C1 pins to this. (History holds a narrow remnant: 3 concrete nov25 paths in a notebook + 27 CT-error UIDs — not the test set.)
