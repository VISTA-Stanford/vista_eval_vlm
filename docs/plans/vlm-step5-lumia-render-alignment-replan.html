Step 1 — reconstruct numeric_value from element text PENDING

_lumia_event_to_row (ehr.py:79-127) currently reads attrib.get("numeric_value") — dead code, since meds2text never emits that attribute. Replace the element-text-to-text_value branch (ehr.py:95-99) and the return dict's dead numeric_value read (ehr.py:116) with a version that attempts float(el_text) before falling back to text_value.

def _num(v):   # already exists at ehr.py:101-105, unchanged — hoist above its first use
    try:
        return float(v) if v is not None and str(v) != "" else None
    except (TypeError, ValueError):
        return None

text_value = attrib.get("text_value")        # dead in practice
numeric_value = _num(attrib.get("numeric_value"))  # also dead in practice
if text_value is None and numeric_value is None:

    if el_text and el_text.lower() not in _STATE_TOKENS:
        parsed = _num(el_text)
        if parsed is not None:
            numeric_value = parsed
        else:
            text_value = el_text

No renderer change needed — get_llm_event_string (meds_timeline_utils.py:222-236) already branches on whichever field is populated.

Cross-repo contract note (Codex review): depends on meds2text's current event_to_xml collapse behavior (textify.py:1273-1340) — note the dependency in ehr.py's docstring so a future meds2text change doesn't silently break this.

Three accepted, byte-level residual classes (all structurally forced by meds2text's export design, not adapter bugs):

  • ~460/5,841 legacy lines shaped VALUE: D.D | NOTE: D.D — event_to_xml keeps only one winning value per event; the loser never reaches the .xml.
  • Zero-valued numerics (Codex-caught). numeric_value or text_value or None treats 0.0 as falsy — a genuine zero-valued lab silently loses; live's element text can be empty for a row legacy renders VALUE: 0.0.
  • Ontology-override collapse (Codex-caught). After picking a winner, event_to_xml can overwrite numeric element text with an OMOP concept description (textify.py:1335-1338) — the number is then unrecoverable for that row.

Verification below reports masked counts for the last two so their real prevalence is known, not assumed negligible.
