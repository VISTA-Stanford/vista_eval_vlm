# VLM Phase 2 — config-context viewer (weight-free HTML)

**Status: Completed** (2026-07-16) · **Codex design-review applied** 2026-07-15 (feedback: `docs/plans/reviews/vlm-phase2-config-context-viewer-feedback.md`; core architecture confirmed sound, ~10 findings applied). **3 residual decisions resolved with Phil 2026-07-15:** Q1 tokenizer cache-miss = **hard STOP** (no estimate); Q2 CLI = **`--type`/`--name`** (Ryan's repo-wide convention); Q3 correctness coloring = **omitted** (the viewer is input-QA only — "we don't need answers"). Follows the landed roadmap (`docs/plans/vlm-modular-preprocessing-and-context-viewer-roadmap.md`, now `Landed — Phase 0 + rungs 0–2 + 3b`). Phase 1 framework + golden harness + model-load split + `supports_inline` already on `main`; this plan is **only the viewer + its two enabling seams**.

> Design decisions locked with Phil (2026-07-15, before drafting):
> - **Reuse = extract a shared weight-free capture core** both `golden_harness` and the viewer consume (zero-drift by construction; golden_harness refactor stays byte-identity-preserving).
> - **Token count = real tokenizer, no GPU** (tokenizer-only load for exact text tokens) + a per-adapter `context_window` for the budget denominator; image count shown as a separate chip.

## Goal

A weight-free CLI that renders **exactly** the context a given `(config, task, experiment, model)` feeds each model — assembled prompt text + the selected CT slices / pathology tiles (post-window, model-ready) as thumbnails, per example, paginated by batch, with a token-budget bar — into **one self-contained HTML file**. The concrete use is **Phil's manual pre-run input QA**: before kicking off a full eval run, eyeball a **small subset** of examples across a couple of VLM tasks to confirm the inputs look correct — prompt text well-formed, right slice counts, no 0-image rows where images are expected. It *instruments* the preprocessing pipeline (`claude_ops.md`: "you don't trust; you instrument") rather than scoring it — it shows **inputs, not answers**. The hard requirement is **zero drift with inference**: it must show what the model actually receives, not a re-derivation.

## Approach

- **Reuse the inference path, not a parallel one.** `golden_harness.capture_experiment` already runs the weight-free loop the viewer needs — build orchestrator (no weights), `_load_experiment_data` → `_build_prompts_for_experiment` → iterate `PromptDataset.__getitem__` directly. At the moment before it hashes, `item["image"]` holds the fully-preprocessed PIL images (post-window, post-pad). **Extract that loop into a shared generator**; golden_harness hashes each item's images, the viewer base64-thumbnails them. One capture path ⇒ zero drift.
- **Render off `PromptDataset`, NOT `context.Assembler`.** The assembler is only partially wired into the hot path today — the flat `{question, image}` that reaches the model is produced by `PromptDataset.__getitem__` (`CTAdapter.contextualize` + inline pathology-tile load) + `_build_prompts_for_experiment`, not `Assembler.to_flat_item`. Rendering via `ContextComposition` would risk showing context inference doesn't feed. Use `context/` block metadata (selector, count, timestamp) only for provenance *labels*.
- **Weight-free but VM-only.** `TaskOrchestrator.__init__` still builds `bq_client` + `storage_client` and the path reads real PHI data (`run_bq.py:99,102`) — so this runs on the VM (Claude-Code CPU box), like the golden harness. No GPU, no model weights. **Retrieval experiments require weights** (`run_bq.py:806`) → rejected at preflight, exactly as golden_harness does.
- **Token budget** = exact text tokens (tokenizer-only load, no GPU; cached on the VM) / a new per-adapter `context_window`. Image-token cost varies per model and isn't computable weight-free → the bar is **text-token** budget; image count is a separate metadata chip with a caveat note.
- **PHI output.** The HTML embeds real de-identified timelines + imagery → written only under `results_dir` (su-vista PHI mount), git-ignored (mirror the golden globs); `/phi-vet` gates every commit. The HTML itself is never committed — only the generator code is.

## Design details

- **CapturedExample carries the PILs.** golden_harness discards images after hashing; the viewer keeps `.images` for thumbnails. Both derive every scalar field from the same `raw_row`/`item`, so the golden bytes are unchanged by the extraction.
- **Assembly order for images.** For `ordered`, images precede text (per `assembler.content_sequence`); the viewer renders thumbnails then the prompt, matching what the model sees. CT = list of windowed slices; pathology = list of tile crops; `None`/empty → an explicit "0 images (no_image row)" flag.
- **Token-budget bar.** `pct = text_tokens / context_window`; color thresholds (e.g. green < 0.7, amber 0.7–0.9, red > 0.9). `context_window == None` → render "context window unknown" (no bar fill). Image count shown beside it with a note that VLM image tokens are model-specific and not included. **Token count is always real (Q1):** the tokenizer-only load is a preflight precondition, so a miss STOPs the run — the bar never shows a fabricated estimate. This keeps the handoff SIMPLE: the STOP is a standard halt-and-report, not a class-2 inline decision gate.
- **No correctness coloring (Q3).** The viewer shows **inputs, not answers** — Phil's use is pre-run input QA on a small subset, not scoring. No `--results-csv`, no `results_analyzer.is_answer_correct` (it needs a model response the weight-free viewer lacks). Card highlighting, if any, is **input-sanity** (0-image-where-expected, empty prompt) only.
- **`summarize` = fail-closed** at preflight (consistent with `assembler.preflight` fail-closing `inline_by_timestamp`). Rationale: the summarize cluster is a deferred, model-backed step; a viewer that silently skipped it would misrepresent the context. (Decided, not asked — low stakes; revisit if/when summarize is wired.)
- **Side-by-side = deferred** (OQ-J: optional/later). First cut is single-column per example. (YAGNI.)
- **Canonical smoke task = PFS `progression_recurrence_free_survival_1_yr`** (OQ-I; `_2_yr` alt). (Decided.)

## Verification & VM handoff

Executed on the **Claude-Code CPU** box (`phil-sllm-01`) — weight-free, holds the `/mnt/su-vista-*` PHI mounts + BQ creds + runs Claude Code (readback here directly). No hcpu/GPU leg, no runner-script split. The Mac is planner-only.

**Classification: SIMPLE handoff** — one repo, one executor class (Claude-Code CPU box, run + readback co-located), no cross-repo SHA ripple, no bank/un-bank beyond the one pre-refactor golden baseline, no destructive writes, no non-Claude runner script. The one prior risk to "simple" — an ambiguous tokenizer fallback — is removed: a tokenizer miss is a **preflight STOP** (halt-and-report), not a class-2 inline decision gate. Every smoke runs on a **small subset** (small `--limit N`) — this is pre-run input QA, not a full pass.

**What runs on the VM (in order):**
1. **golden_harness byte-identity regression (proves the extract is a no-op).** Re-bank a small golden post-refactor (`golden_harness … --limit N`) and `diff_golden … --mode strict` it against a **pre-refactor** bank of the same `(task, experiment, model, N)` (bank the "before" on the pre-refactor SHA first, or reuse a banked C1/C3 golden if `(task,experiment,model,N)` matches).
2. **Run the viewer on the canonical smoke — small subset only.** `context_viewer --config <cfg> --type <gemma3|intern> --name <model name> --task progression_recurrence_free_survival_1_yr --experiment <ct-bearing exp> --limit N` with **N small (≈5)** — this is pre-run input QA, so keep every smoke on a small subset to save time; then a `no_image` experiment; open each HTML.
3. **Preflight / edge cases (each must fail-closed with a clear message, no weights touched):** a **retrieval** experiment → rejected; a **`summarize`**-configured experiment → rejected; an **unknown `--experiment`** → rejected; an **invalid `--type`** → rejected; a **block-list dict** experiment → resolves via `normalize_experiments` (renders) or rejects cleanly; a **model whose tokenizer will not load** (wrong `cache_dir` / no `HF_TOKEN` / uncached) → **STOP** with a diagnostic (Q1). *(No correctness-coloring case — the viewer has no `--results-csv`; Q3.)*

**Expected (per step):**
- Step 1 — `RESULT: ALL GATES PASS`, exit 0; shared-index set == N; `STRUCTURE_FIELDS` byte-identical. (The refactor changed *no* golden bytes.)
- Step 2 — HTML file exists, non-empty, and **structurally self-contained**: grep shows **no `http://` / `https://`**, no remote CSS/JS/font/image refs, and **no local filesystem paths in any `<img src>`** (base64 data-URIs only). Exactly N example cards (N small); each CT-bearing card shows the assembled prompt + the right **slice count** (matches the selector, e.g. 30 for `axial_all_image`) as thumbnails + a token-budget bar; the `no_image` run shows **0 images** on every card and flags it; the token bar shows a **real** token count with denominator == the model's `context_window` (or "unknown" for a `None` adapter). (If the tokenizer can't load, the run STOPs at preflight — it never reaches this step with a fake bar.)
- Step 3 — every reject case exits non-zero with its message and touches no weights/GPU; the dict-experiment case renders or rejects cleanly; a tokenizer-load failure STOPs with its diagnostic.

**Expected-vs-unexpected envelope (pre-declared, so benign surprises resolve inline):**
- **Tokenizer cache-miss → STOP (not an envelope item).** The load is a preflight precondition; a miss halts with a diagnostic (model + likely cause: `cache_dir` / `HF_TOKEN` / uncached / offline). This is a **halt-and-report** — the executor doesn't decide inline; it reports back and Phil picks the remedy (Q1).
- **`context_window == None` for a `None`-table adapter → ACCEPTED**: bar reads "unknown". Only a *wrong* denominator (non-None but implausible) is unexpected.

**Stop (per step):**
- Step 1 — any `GATE FAILURE` / non-zero exit / index-set mismatch ⇒ the extraction was **not** byte-preserving → **hard halt**, fix the refactor before anything else (this is the whole safety of "extract shared core").
- Step 2 — HTML references any external URL or leaks a local image path in `src` (not self-contained); a CT-bearing row renders 0 images or a **wrong** slice count (drift — the viewer isn't reading the inference path); weights/GPU touched (preflight failed to fail-closed).
- Step 3 — any reject/STOP case does **not** fire (renders instead of rejecting, loads weights, or a tokenizer miss doesn't halt) ⇒ preflight is broken → halt.

**Also verify:** the new viewer-output glob is present in `.gitignore` (parallel to `*_golden.jsonl` / `golden/`) so the HTML can never be committed.

**PHI:** the HTML is PHI (real timelines + imagery) → lives only on the su-vista mount, git-ignored, never committed; readback reports **counts / file existence / slice counts / token numbers only** — never paste prompt text, timeline, or image data. `/phi-vet` gates the code commit.
