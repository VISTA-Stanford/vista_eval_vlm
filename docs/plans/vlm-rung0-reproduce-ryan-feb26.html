Gotchas

⚠ The 0c comparison is confounded — even the ±image delta

Current arms vs Ryan's arms differ in two ways beyond the image: (1) report presence — current no_image/axial_all_image use the report-inclusive timeline (use_no_report_csv=False), Ryan's timeline_only/image_and_timeline use the report-stripped timeline; (2) slice count — axial_all_image=30 slices (presets.py:84), Ryan's image_and_timeline (raw no_report)=10 (presets.py:92). So absolute accuracies aren't comparable, and the ±image delta measures the image's marginal value under different text+dose conditions — one weak directional signal, not confound-robust.

Prefix swap must actually exercise the feb26 reroute (no-op / silent-fallback risks)

Two ways the "reproduce on feb26" claim can be hollow: (1) the resolver's startswith(prefix) early-return means a stored nifti_path shape may reconstruct differently per shape — the 0a preflight classifies shapes before trusting it; (2) the local ct_dir nov25 cache is tried before GCS, so if it survives the run loads local nov25 and never proves the reroute — hence force-GCS (leave ct_dir unset). A local-cache "exact Ryan" run is a separate optional ryan_exact_local outcome, not the gate.

"Ryan + declared deltas" — not a digit match

This branch carries two deterministic input changes vs Ryan's original code: the 30-slice even-spacing fix (vqa_dataset.py:191-210, 04b97d8) on the axial_all_image path, and the unit_source_value EHR remap. Fine for an operability/sanity smoke; if a true digit reproduce is wanted, cherry-pick only the prefix swap onto Ryan's baseline SHA.
