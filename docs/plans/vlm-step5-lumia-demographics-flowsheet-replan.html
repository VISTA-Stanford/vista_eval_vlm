Step 5 re-plan: close the parse_lumia demographics gap, accept the flowsheet divergence, re-verify

Phil's call: fix the bug, accept the exclusion, re-measure. This plan adds the fix, a new comparison mechanism for the accepted exclusion, and re-runs the original plan's Phase 1 decision gate.

Phase 0.5 and the diff_golden.py mechanism can proceed in parallel — the CLI flag has no dependency on the VM's schema confirmation. The ehr.py fix specifically needs Phase 0.5's code/description conventions first, per the plan's "don't speculate" discipline.

Knobs and contracts

--exclude-line-patterns (new CLI flag, diff_golden.py)

Type: list of substrings. Default: empty (no exclusions — existing non-EHR callers unaffected). Applied to both BEFORE and AFTER text, before the existing normalize_text comparison. Distinct from normalize_text's allowlist: this drops whole lines for a declared, permanent divergence, not a formatting delta.

diff_golden ... --mode strict --exclude-line-patterns "STANFORD_OBS/Flowsheet"

Demographic pseudo-event row shape (new, ehr.py)

Synthesized rows use the exact same shape _lumia_event_to_row already produces — time / code / description / numeric_value / unit / text_value — so get_llm_event_string renders them with zero special-casing. Exact code/description string conventions are VM-confirmed in Phase 0.5, not guessed here (see Open Questions).

_lumia_event_to_row attribute fix

- "type": attrib.get("type"),
+ "type": attrib.get("table"),

Matches meds2text's real emitted attribute (textify.py's attribute_order defaults to ["table", "code", "name"]). Fixes a silently-broken field for any future type-keyed filter; doesn't affect the demographics or flowsheet gap directly.

Gotchas

The "before" bank runs old code — it can't be reconfigured

Phase 1's before-bank is generated from a worktree at the pre-wiring parent SHA. That code has no concept of select/code_filter chains at all — changing the after-side's config can only ever reduce the after-side's content, never make legacy's baked-in patient_string exclude flowsheets it already contains. This is why a new comparison mechanism (step 4) is necessary rather than optional.

markup.md is a known-incomplete schema doc

It documented type= instead of the real table= attribute, and originally listed fewer fields than real files carry. Don't treat its silence on a Race field as proof Race is absent from real XML — that needs an empirical VM check (Open Questions).

PHI discipline when inspecting the already-banked golden file

Report the structural pattern only (e.g. "MEDS_BIRTH as a bare code, no description" or "Gender/FEMALE-style value-in-code") — never a real patient's actual rendered line. Same discipline as the existing plan's Phase-2/Step-3 PHI notes.
